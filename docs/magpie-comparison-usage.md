# Magpie 功能对比与用量模块重构

本文基于本地 `C:\guodevelop\demo\magpie` 与当前网关工作区的源码比较。比较对象是当前文件内容，未锁定发布版本。核查重点为用量、额度刷新、日志关联、权限隔离及故障转移；不代表所有协议与所有上游接口均经过联网验证。浏览器截图采用合成测试数据，无真实账户凭证。

## 功能对应与架构差异

| 领域 | 当前网关 | Magpie | 判断 |
| --- | --- | --- | --- |
| 协议接入 | OpenAI Chat、Responses、Claude 的转换及直通，独立 Go HTTP 服务 | 网关、桌面/终端/GUI 入口及插件体系 | 共有协议能力，组织方式不同；不能因代码不同判断错误 |
| Provider 与账号 | Provider 绑定凭证，API 密钥配置路由及备用链 | Provider 下多个密钥/账号候选，支持排序、轮转、按用量选择 | 路由粒度不同，不能直接照搬账号调度 |
| 故障转移 | 区分软故障、硬额度/认证故障及请求拒绝，维护 Provider 冷却与恢复探测 | 按账号/模型记录休眠，区分余额、额度、限流、限制和请求拒绝 | Magpie 的分类与恢复时间更细；当前策略差异本身尚不能认定为故障 |
| OAuth 与额度 | 多家上游内置，前端缓存、周期刷新与强制刷新 | 额度卡片与用量分层，刷新时防止旧响应覆盖较新的读取 | 防止异步结果串账号是共同需求，当前实现存在已修复问题 |
| 用量 | 永久日聚合与有保留期的请求日志并存；按模型、Provider、密钥、协议、用户汇总 | 用量插件负责总览、趋势、分组、请求等视图；订阅额度独立呈现 | 参考其信息层次，保持本项目自己的数据契约 |
| Token | 输入包含缓存读取与相应协议的缓存创建；缓存读取是输入的子集 | 输入、缓存读取、缓存写入独立，部分展示重新合成 prompt | 字段不能逐项照抄，否则重复计数 |
| 用户与权限 | 管理员/普通用户，普通用户通过自己拥有的密钥隔离请求数据 | 用量 API 根据调用身份和权限限制可见数据 | 统计与日志关联都必须在后端保持隔离 |
| 扩展功能 | RTK 压缩、额度保活、公网 Tunnel、机器状态等 | 插件体系及其各自管理功能 | 非等价功能不应强行映射到同一页面 |

Magpie 当前代码中，一些原有 Provider 已迁移至社区插件；迁移或退休代码不能当作仍在服务请求的完整实现。本次未检查独立社区插件仓库，也未更改 Magpie。

## 已确认并处理的问题

### 1. 今日统计被所选区间覆盖

`internal/gateway/server.go` 曾在区间请求数大于今日请求数时，把区间总计和分类复制到 Today。选择多日区间就可能把昨天请求算入“今日”。管理员与普通用户分支均删除该覆盖逻辑。

回归：昨天两次、今天一次，区间应为三次、今日应为一次；覆盖管理员与普通用户。

### 2. 日期切换的旧响应覆盖新区间

原请求没有读取版本控制。快速选择两个区间时，较慢的旧请求可能最后完成并覆盖新状态。现在用请求版本和登录缓存作用域检查丢弃过期结果；页面同时验证响应日期与当前选择相符。RTK 的独立区间读取也加上版本控制。

参考 Magpie 用量客户端对读取序号、区间和视图的检查。浏览器通过人为延迟 7 天请求、随后选择 30 天验证。

### 3. 额度响应及缓存可能串账号

`useOAuthUsageReport` 原先在请求完成时使用可变的当前 path 写缓存，旧账号请求可能被写到新账号的缓存键。现在捕获请求路径、检查版本及启用状态，切换路径时读取该路径自己的缓存，并使卸载前请求失效。

浏览器延迟账号 A 响应，切到账号 B，验证最终展示为 B、loading 结束、缓存没有写入 A 的旧结果。

### 4. 展示了没有关联数据支撑的交叉分析

旧用量页面部分钻取只是改变标签，仍使用全局独立聚合，无法证明某个模型与 Provider/密钥的实际关联。新页面只展示接口提供的五种独立分类，不再把全局总量标成筛选后的关联数据。真实请求关联通过日志查询完成。

### 5. 日志入口筛选不准确

模型入口原先使用当前页的前端关键词过滤，不能在所有分页日志中定位；密钥入口按名称匹配，同名密钥会混合。新增后端精确 `model`、`apiKeyId` 查询参数。密钥 ID 条件与身份允许的密钥集合求交集，不能越过普通用户隔离。

回归在内存与 SQLite 两条查询路径分别验证模型精确匹配、同名密钥、自己的密钥与他人的密钥。页面显示来自用量的精确条件，并可重置。

### 6. Qoder 额度重置时间丢失

上游额度桶解码结构没有保留重置字段，之后再序列化、解析也无法找回。补充 `resetsAt`、`reset_at` 原始字段并直接解析；两种字段均有回归用例。

### 7. 指标表达不准确

无状态记录时不再推测成功率为 100%，改为未知。总 Token 只加输入和输出，不重复加缓存。旧区间 TTFT 缺少有效计时样本数，不能按总请求数加权，重构页面暂不显示这一不可靠结果。

### 8. 普通用户分类在日志过期后丢失，启动可能清空历史

新增按密钥关联 Provider、模型、输出协议的永久日桶，并持久化每个密钥的状态、耗时和有效 TTFT 样本数。普通用户先按所属密钥筛选，再合并分类，避免跨用户泄漏。总量、分类和状态不再依赖内存日志存活。

启动直接加载永久聚合；升级时先完整分页读取日志，再通过事务补齐能够确认日志完整的日期。保留既有请求总量、Token 和流量字节数，不再清空日桶或用有限日志覆盖历史。日志读取失败不会清空数据，也不会将迁移标记为成功。缺失整天聚合时可从保留日志建立数据。

回归覆盖：40 天前两组密钥的数据在无请求日志时重启，普通用户只看到自己的分类；连续重启不丢失、不重复；不完整日志不覆盖已有分类；完整日志反复回填后总量和字节数保持不变。

## 新用量页面

主结构改为四个职责不同的模块，统一使用日期区间：

| 模块 | 与 Magpie 对齐的职责 | 当前实现与数据口径 |
| --- | --- | --- |
| 概览 | 总量、来源、趋势 | 永久日汇总；请求、输入/输出/缓存、收发字节趋势；今日/本月；保留明细的小时分布；模型、Provider、密钥、协议、用户排行 |
| 请求 | 单次调用、筛选、性能 | 按模型、Provider、密钥、状态、推理设置筛选；耗时中位数/P90；有效流式首字与近似输出速度；六阶段耗时；缓存写入；CSV |
| 会话 | 多轮累积消耗 | 明确会话标识按密钥摘要隔离；请求与错误数、累计 Token、中位数/P90、首末输入变化、展开调用序列；无标识请求单独计数 |
| 上下文 | 输入规模、组成、缓存、优化 | 输入中位数/P90、缓存读写、结构采集覆盖、系统/消息/工具 JSON 字节组成、大上下文请求；RTK 独立区间 |

会话与上下文基于保留的请求日志。新请求在正文裁剪前采集数字结构，不依赖开启成功请求正文落盘；旧记录缺失的字段显示未采集。Magpie 的项目目录、技能与工作时长来自本机 Agent 文件，本项目尚无该数据源，不使用网关请求推造这些指标。品牌图标复用现有 `BrandIcon` 与 Provider 图标解析器，模型通过模型目录关联 Provider。

- 将页面从 `main.tsx` 拆成 `components/usage.tsx` 与局部 `usage.css`，入口只保留状态与请求协调。
- 总览保留总请求、总 Token、缓存命中率、请求成功率。
- 趋势一次只展示一个指标，可选请求数、总/输入/输出/缓存 Token、接收/发送字节；支持悬停、键盘读取和精确数据表。
- 模型 / Provider / API 密钥 / 输出协议 / 用户五类明细支持搜索、分页、占比和适用的日志入口；普通用户不显示用户维度。
- RTK 使用独立区间，不与网关请求 Token 混为同一数据源。
- 额度留在 Provider 页面，避免把请求统计与订阅剩余额度混淆。
- 使用主题令牌、轻分隔线与表格行，减少层层卡片。手机图表和表格局部滚动，页面不横向溢出。
- CSV 正确处理引号和换行，并为危险公式起始字符添加文本前缀。

## 尚存的数据限制

存储重构修复了新数据的长期分类持久化，但不能恢复已经删除的原始关联：

1. 升级前已过期、或与永久总量不匹配的旧日志无法证明密钥与模型/Provider 的关联。这些旧日期保留总量；缺失的分类、状态或耗时不会伪造补全。
2. 启用永久聚合存储时，API 不再用最多 5000 条日志覆盖总量、分类和状态。小时细节仍受内存日志范围限制；没有永久聚合存储的兼容路径仍使用有限日志补齐。
3. 日桶采用服务端本地日期，浏览器可提交带时区的区间；跨服务端/浏览器时区和夏令时切换需要独立回归与明确产品口径。部分日期边界仍使用固定 24 小时。
4. 精确日志按存储的模型字段匹配，不代表自动合并所有上游模型别名；历史日志同样受保留期限制。
5. 本轮未完成所有上游的真实账户联网测试，未据此声称路由、OAuth 或协议转换不存在其他缺陷。

后续可扩展 API 的历史覆盖范围和计时样本数元数据，以及独立的永久小时聚合。当前页面不以请求日志的有限样本宣称完整历史。
